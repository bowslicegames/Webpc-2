## Fixes made

### Network and proxy
- Streamed HTTP response bodies through the QEMU-Wasm bridge instead of buffering entire responses.
- Added bounded response queuing and 64 KiB bridge slices, including when Fetch supplies unusually large chunks.
- Preserved the order of queued socket reads when the shared-memory lock is busy.
- Kept lock contention and certificate retrieval asynchronous; no blocking `Atomics.wait` remains in the receive path.
- Revalidated every guest HTTP(S) redirect against protocol, credentials, port, and host allowlist rules.
- Rejected HTML error pages where a binary download was requested and returned useful upstream diagnostics.
- Added live tests for a 40 MiB direct/proxy byte-for-byte download, Alpine APK index gzip integrity, and the configured BellSoft Java 21 APK endpoint.

### Runtime assets and startup
- Validate cached and downloaded runtime assets against their known byte sizes before using or caching them.
- Delete invalid cached assets and reject HTML responses instead of saving them as runtime binaries.
- Rotate the browser asset-cache version whenever the dynamic disk release workflow runs.
- Keep the Worker-pinned `stack.js` revision and the startup size manifest synchronized.
- Preserve the startup error log and make the cache reset action explicit about session data loss.

### File Manager and desktop command handling
- Corrected the File Manager home directory: the guest image has the root account at `/root`; `/home/webpc` does not exist.
- Set the initial File Manager location to `/root/Desktop` and create `Desktop`, `Documents`, and `Downloads` when the guest shell becomes ready.
- Use filesystem metadata (`stat -c %s`) for file sizes rather than reading file contents to count bytes.
- Verify uploaded file sizes and report non-zero guest command exit statuses to desktop apps.
- Use safe shell quoting for paths and allow ordinary printable Linux filenames while rejecting traversal and control characters.
- Clarified in the UI that guest files remain on the temporary VM disk and do not survive a fresh VM launch.

### Network diagnostics
- Extended the in-guest Network Test to download the Alpine v3.21 package index and verify its gzip integrity. This is intended to isolate the guest-to-proxy path behind the earlier `wget`/APK errors.

## Remaining work — not honestly a complete PC yet

1. **Guest-side networking still needs an iPad test.** The Worker and bridge tests pass separately, but they cannot prove that the running Alpine guest on the iPad successfully reaches the proxy. Use the desktop's Network Test and then try `apk update` and `apk add nano`.
2. **Guest disk persistence is not implemented.** The Cache Storage cache preserves the original runtime assets, not guest changes. A CI scan of the published `out.js` found no recognizable IDBFS, OPFS, or IndexedDB backend. Durable guest storage requires rebuilding and verifying the QEMU-Wasm runtime with a persistent filesystem/block backend.
3. **The guest is headless and serial-only.** The current QEMU launch uses a serial console; there is no Linux graphical display/GPU path. The browser desktop is a shell around the terminal, not a full Linux desktop environment.
4. **Desktop apps still share one serial transport.** Their browser-side queues are separate, but this is not the independent guest service/virtio-serial architecture originally requested.
5. **The current 512 MiB guest RAM and headless display are not suitable for a practical Minecraft Java client.** Java runtime installation and a graphical Minecraft launcher/client remain separate work.
6. **iPad-specific validation remains necessary.** CI runs on GitHub-hosted Linux/Node environments; it cannot reproduce iOS WebKit memory pressure, storage quotas, tab suspension, or touch behavior.

## Follow-up GPU and memory work — 2026-11-03

- Added host WebGL capability diagnostics that report the browser-visible renderer and basic texture/renderbuffer limits. The temporary WebGL context is explicitly lost immediately after inspection to avoid holding a GPU context open unnecessarily.
- Added guest RAM/swap inspection and an opt-in ZRAM control in the Virtual Computer panel. If the Alpine kernel exposes `/sys/block/zram0` (or can load the `zram` module), it configures a 128 MiB logical compressed swap device, prefers LZ4 when the kernel lists it, and sets swappiness to 80. It never creates a disk swapfile. If kernel support is absent, the control reports that and makes no change.
- ZRAM is not additional physical RAM and does not borrow WebGL VRAM. Its physical memory use is dynamically allocated and compression consumes CPU. The 128 MiB value is a logical swap capacity, not a guaranteed 128 MiB of extra usable memory.
- The QEMU guest remains at 512 MiB RAM. This was deliberately not raised because the iPad browser must also hold QEMU-Wasm, the guest disk backing, terminal, and browser UI; a larger guest allocation could increase tab termination risk.
- No OpenGL-to-WebGL bridge was added. The current QEMU-Wasm binary is launched with `-nographic` and has no verified display backend or GPU transport. Adding a virtual VGA device alone would not connect it to a browser canvas. A real bridge needs a QEMU display backend and a compatible guest OpenGL translation path, followed by an end-to-end LWJGL test.
- No swapfile was added. Disk-backed swap remains disabled.

The ZRAM action is intentionally opt-in and requires testing on the running Alpine guest. CI can validate the browser JavaScript and UI invariants, but cannot prove that this specific guest kernel includes a loadable ZRAM module or that compression improves performance on the target iPad.
